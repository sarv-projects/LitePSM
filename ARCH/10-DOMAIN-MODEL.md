# Domain Model & Canonical Identifiers

Struct blocks below are transcribed from `internal/domain` (Go 1.26) and match the
tree at `ff0a1db`. Where a type exists but production code never writes it, the
subsection says so using the state vocabulary of [`STATUS.md`](../STATUS.md)
(`DESIGNED` / `IMPLEMENTED` / `WIRED` / `TESTED` / `VERIFIED` / `SHIPPED`).

## 1. Canonical Identifier Grammars

Display names and titles are mutable and non-unique. All internal operations, database primary keys, and cryptographic hashes rely strictly on canonical, immutable identifier grammars.

```text
┌─────────────────┬──────────────────────────────────────────────────────────────────┐
│ Identifier Type │ Canonical Format & Grammar                                       │
├─────────────────┼──────────────────────────────────────────────────────────────────┤
│ SourceId        │ <namespace>:<slug>                                               │
│                 │ Regex: ^[a-z0-9_-]{3,32}:[a-z0-9_-]{3,64}$                       │
│                 │ Example: builtin:mcp-registry, git:anthropic-official            │
├─────────────────┼──────────────────────────────────────────────────────────────────┤
│ ListingId       │ <kind>:<source-id>:<percent-encoded-upstream-id>                 │
│                 │ Regex: ^(plugin|mcp|skill|connector|agent|rule|hook|tool|lsp):   │
│                 │        [a-z0-9_:-]+:[A-Za-z0-9_.~%+-]+$                          │
│                 │ Example: mcp:builtin:mcp-registry:%40modelcontextprotocol%2Fpg   │
├─────────────────┼──────────────────────────────────────────────────────────────────┤
│ ComponentId     │ <listing-id>@<resolved-version>#<kind>/<component-name>          │
│                 │ Example: mcp:builtin:mcp-registry:pg@1.4.0#mcp-provider/server   │
├─────────────────┼──────────────────────────────────────────────────────────────────┤
│ PlanId          │ plan_<26-char Crockford base32>                                  │
│                 │ Regex: ^plan_[0-9A-Za-z]{26}$ (schemas/install-plan.schema.json) │
│                 │ Example: plan_01J9X8K2M4N5P6Q7R8S9T0U1V2                         │
├─────────────────┼──────────────────────────────────────────────────────────────────┤
│ InstallId       │ inst_<scope>_<listing>_<digest8>                                 │
│                 │ Regex: ^inst_[0-9A-Za-z_-]{10,64}$                               │
│                 │ Example: inst_user_mcp_builtin_mcp-registry_a1b2c3d4             │
├─────────────────┼──────────────────────────────────────────────────────────────────┤
│ CapabilityId    │ <install-id>/<component-name>/<provider-native-tool-name>        │
│                 │ Example: inst_user_mcp_builtin_mcp-registry_a1b2c3d4/server/q    │
└─────────────────┴──────────────────────────────────────────────────────────────────┘
```

Authority for these grammars is `internal/domain/identifiers.go`:

*   `RegexSourceID` (`:13`), `RegexListingID` (`:17`), `RegexInstallID` (`:21`), `RegexDigest` (`:24`).
*   **ListingId kinds** are the full nine-value `ListingKind` enum — `plugin`,
    `mcp`, `skill`, `connector`, `agent`, `rule`, `hook`, `tool`, `lsp`
    (`internal/domain/models.go:8-19`). `connector` is a deferred v2 value that
    never appears in the shipped dataset ([ARCH/26 §3.4.1](26-ECOSYSTEM-IA-PACKAGE-MODEL.md)).
*   **PlanId** is generated by `newPlanID()` (`cmd/litespm/main.go:1803-1818`):
    `crypto/rand` masked over the Crockford base32 alphabet `0123456789ABCDEFGHJKMNPQRSTVWXYZ` (`I`, `L`, `O`, `U` excluded).
*   **InstallId** is generated by the install engine as
    `fmt.Sprintf("inst_%s_%s_%s", opts.Scope, safeListing, digestShort)`
    (`internal/install/engine.go:435`), where `safeListing` is the listing id with
    every character outside `[A-Za-z0-9_-]` replaced by `_` and `digestShort` is
    the first 8 hex characters of the committed tree's `sha256:` digest
    (`internal/install/engine.go:425-434`). The regex deliberately admits
    `inst_<26-char-ULID-or-UUIDv7>`-shaped values as well (comment at
    `internal/domain/identifiers.go:19-20`), but **the engine never mints them** —
    the scoped, content-derived form above is what production writes. Both forms
    are admissible to `ParseInstallID`.

## 2. Core Domain Entities

### 2.1 Listing
Represents a normalized discovery entry in the LiteSPM catalog.
```go
type Listing struct {
    SchemaVersion        int                   `json:"schemaVersion"`
    ID                   string                `json:"id"` // ListingId
    Kind                 ListingKind           `json:"kind"` // plugin | mcp | skill | connector | agent | rule | hook | tool | lsp
    Name                 string                `json:"name"`
    Title                string                `json:"title,omitempty"`
    Summary              string                `json:"summary"`
    Description          string                `json:"description,omitempty"`
    Categories           []string              `json:"categories"`
    Keywords             []string              `json:"keywords"`
    PublisherClaim       PublisherClaim        `json:"publisherClaim"`
    Source               SourceReference       `json:"source"`
    Versions             []VersionSummary      `json:"versions"`
    ComponentsSummary    []ComponentSummary    `json:"componentsSummary"`
    RequirementsSummary  []string              `json:"requirementsSummary"`
    CompatibilitySummary []CompatibilityFact   `json:"compatibilitySummary"`
    VerificationSummary  VerificationSummary   `json:"verificationSummary"`
    Provenance           ProvenanceRecord      `json:"provenance"`
    Status               ListingStatus         `json:"status"` // active | stale | deprecated | withdrawn | unavailable
    RawMetadataRef       string                `json:"rawMetadataRef,omitempty"`
}
```
**Written in production?** Not as database rows. Listings are emitted by
`internal/catalogbuild.CompileRelease` (`TESTED`, non-test caller `litespm catalog build`,
[STATUS.md](../STATUS.md) §2) and, for the deployed site, by
`scripts/build_full_catalog.py` into `web/data/catalog.json` (`WIRED` deployed
producer, [STATUS.md](../STATUS.md) §6). The `sources` / `source_snapshots` /
`catalog_releases` tables have no production writer.

### 2.2 VersionRecord
Represents a specific release of a listing with resolved artifact pointers.
```go
type VersionRecord struct {
    ListingID           string                  `json:"listingId"`
    Version             string                  `json:"version"` // Display version
    ImmutableRef        string                  `json:"immutableRef,omitempty"` // Pinned Git SHA / registry digest
    SourceSnapshotID    string                  `json:"sourceSnapshotId"`
    Artifacts           []ArtifactRef           `json:"artifacts"`
    Components          []Component             `json:"components"`
    Dependencies        []DependencyConstraint  `json:"dependencies"`
    Requirements        []Requirement           `json:"requirements"`
    PermissionsDeclared []PermissionDeclaration `json:"permissionsDeclared"`
    CompatibilityClaims []CompatibilityFact     `json:"compatibilityClaims"`
    TestEvidence        []TestEvidenceRecord    `json:"testEvidence"`
    Signatures          []SignatureRecord       `json:"signatures,omitempty"`
    PublishedAt         *time.Time              `json:"publishedAt,omitempty"`
    FetchedAt           time.Time               `json:"fetchedAt"`
    RawMetadataRef      string                  `json:"rawMetadataRef,omitempty"`
}
```
**Two distinct declaration types, both real — neither replaces the other.**
`PermissionDeclaration` (`internal/domain/models.go:218-223`: `type`, `target`,
`description`) is the package-level *requested access* list on `VersionRecord`.
`EffectDeclaration` (`internal/domain/models.go:264-269`) is the side-effect
taxonomy carried by `Component.DeclaredEffects` and evaluated by
`internal/policy` (§2.9).

### 2.4 Component
A discrete runnable or readable sub-element within a package.
```go
type Component struct {
    ID                string               `json:"id"` // ComponentId
    Kind              ComponentKind        `json:"kind"` // skill | mcp-provider | hook | command | agent-definition | agent | rule | tool | lsp | asset
    Name              string               `json:"name"`
    Path              string               `json:"path,omitempty"`
    SourceArtifactID  string               `json:"sourceArtifactId,omitempty"`
    HostExtensions    map[string]any       `json:"hostExtensions,omitempty"`
    Runtime           *RuntimeDescriptor   `json:"runtime,omitempty"`
    DeclaredEffects   []EffectDeclaration  `json:"declaredEffects"`
    SupportedByLiteSPM SupportLevel        `json:"supportedByLiteSPM"` // yes | partial | no | unknown
}
```
`HostExtensions` is the intended home for host- or vendor-specific metadata
(e.g. the preserved proprietary namespace discussed in
[ARCH/09 §4](09-RESEARCH.md)); **no adapter populates it today** (`DESIGNED`).

### 2.5 InstallRecord & Project-Scoped State
Captures an installed component bound to a scope and, for project-scoped installs, the canonical workspace:
```go
type InstallRecord struct {
    InstallID        string           `json:"installId"` // inst_<scope>_<listing>_<digest8>
    ListingID        string           `json:"listingId"`
    Version          string           `json:"version"`
    TreeDigest       string           `json:"treeDigest"` // Content-addressed tree SHA-256
    Scope            InstallScope     `json:"scope"` // "user" | "project"
    WorkspaceID      string           `json:"workspaceId,omitempty"` // Canonical workspace hash/id (required if scope=project)
    ProjectRoot      string           `json:"projectRoot,omitempty"` // Absolute filesystem path to workspace root
    Status           InstallStatus    `json:"status"` // "active" | "disabled" | "broken" | "removed"
    InstalledAt      time.Time        `json:"installedAt"`
    UpdatedAt        time.Time        `json:"updatedAt"`
}
```
**Written in production:** yes — `CommitInstallOperation` persists the record and
its `InstallComponentRecord` (`internal/install/engine.go:462` →
`internal/state/repositories.go:343`). No production path reaches this writer
today: no archive artifact source is supplied, so MCP/plugin installs fail
closed (`LPSM-ARTIFACT-UNAVAILABLE`). Skill installs are recorded as ordinary
`InstallRecord` rows through the skills ledger path ([STATUS.md](../STATUS.md) §3).

### 2.8 CapabilityGrant & Identity Binding
Authorizations granted by policy or user approval are strictly bound to cryptographic identity tuples:
```go
type CapabilityGrant struct {
    GrantID              string           `json:"grantId"`
    CapabilityID         string           `json:"capabilityId"` // <install-id>/<component-name>/<tool-name>
    SchemaFingerprint    string           `json:"schemaFingerprint"` // SHA-256 of JCS(tool.inputSchema)

    // Identity binding: Local provider requires CASTreeDigest; Remote provider requires EndpointOrigin + ServerVersionDigest
    CASTreeDigest        string           `json:"casTreeDigest,omitempty"` // Verified CAS tree digest (local)
    EndpointOrigin       string           `json:"endpointOrigin,omitempty"` // Verified HTTPS origin (remote)
    ServerVersionDigest  string           `json:"serverVersionDigest,omitempty"` // Upstream remote server release digest

    Status               string           `json:"status"` // "active" | "consumed" | "revoked" | "expired"
    ExpiresAt            *time.Time       `json:"expiresAt,omitempty"`
    CreatedAt            time.Time        `json:"createdAt"`
}
```
**Never written in production.** `SaveCapabilityGrant`
(`internal/state/repositories.go:451`) has no non-test caller, so the
`capability_grants` table is empty in every real run and **`ExpiresAt` is never
set on a real grant** — the expiry clause in `GetActiveGrant` (`expires_at
IS NULL OR expires_at > CURRENT_TIMESTAMP`, `internal/state/repositories.go:475-481`)
and the grant query in `internal/policy` (`internal/policy/engine.go:261-266`)
therefore match nothing today. The struct, its writer, and its readers are
`IMPLEMENTED`; production grant issuance is `DESIGNED`
([STATUS.md](../STATUS.md) §4).

## 3. Cryptographic & Canonical Hashing (RFC 8785)

To guarantee that hashes remain byte-identical across platforms, architectures, and programming languages, all object hashing uses **RFC 8785 (JSON Canonicalization Scheme - JCS)** followed by SHA-256. `CanonicalizeJSON` takes `[]byte` and returns `([]byte, error)` (`internal/domain/canonical.go`), and every helper below returns the `sha256:<hex>` prefixed string form that `RegexDigest` validates.

### 3.1 Plan Hash (`planHash`)
Computed by `ComputePlanHash` (`internal/domain/canonical.go:19-57`) over the canonical JSON of the execution-relevant fields of `InstallPlan`:
```text
planHash = "sha256:" + hex( SHA-256( JCS({
  "schemaVersion":    plan.SchemaVersion,
  "catalogReleaseId": plan.CatalogReleaseID,
  "request":          plan.Request,
  "resolved":         plan.Resolved,
  "effects":          plan.Effects,
  "preconditions":    plan.Preconditions,
  // included only when non-nil:
  "sourceSnapshots":  plan.SourceSnapshots,
  "hostChanges":      plan.HostChanges,
  "providerLaunches": plan.ProviderLaunches,
  "requestedAccess":  plan.RequestedAccess
})) )
```
*   Verified field-for-field against `ComputePlanHash` in this pass: the four
    conditional keys are omitted from the object entirely when the pointer/slice
    is `nil`, which changes the canonical bytes and therefore the hash.
*   **Excluded:** the volatile fields `planId`, `createdAt`, `expiresAt`
    (`internal/domain/canonical.go:18`), **and** `plan.approval` —
    `PlanApproval` is execution-irrelevant to the hash by design, so approval
    must bind to `planHash`, never be hashed into it
    ([ARCH/06 — Cryptographic Plan Hashing Rule](06-API-CONTRACTS.md)).
*   The daemon persists `planHash` with every plan (`db.SavePlan`,
    `cmd/litespm/main.go:1391` → `internal/state/repositories.go:16-41`) and the
    install engine recomputes and compares it before executing
    (`internal/install/engine.go:107-114`, [STATUS.md](../STATUS.md) §3).

### 3.2 Schema Fingerprint (`schemaFingerprint`)
Computed by `ComputeSchemaFingerprint(jsonSchema []byte)` (`internal/domain/canonical.go:60-72`) over a provider tool's input JSON Schema:
```text
schemaFingerprint = "sha256:" + hex( SHA-256( JCS( tool.InputSchema ) ) )
```
If an upstream server alters its parameter types, adds required parameters, or modifies property descriptions, `schemaFingerprint` changes immediately. The value is what `CapabilityGrant.SchemaFingerprint` binds to (§2.8) and what `mcpclient.FingerprintSchema` / `DetectDrift` recompute (`internal/mcpclient/probe.go:20,67`); drift detection is `IMPLEMENTED` with zero production importers ([STATUS.md](../STATUS.md) §4).
