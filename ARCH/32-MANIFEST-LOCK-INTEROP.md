# Manifest, Lockfile & Interoperability

Status: **`WIRED` for §2–§4 (manifest, lockfile, lock verbs, `install --frozen`) and for four of the §5 importers (`litespm import`: skills-lock.json, server.json, marketplace manifests, plugin.json — import-only, plan preview before every write, `LPSM-IMPORT-001..007`); `DESIGNED` for the remaining §5 rows (OpenAPM, Docker MCP profiles, export) and §6 identity/alias graph.** `litespm.yml` is authored by hand and parsed by `manifest.Load`; `litespm.lock` is written beside it by `litespm lock`. The verbs and the frozen gate ship in `cmd/litespm/lock.go` with 13 tests (`cmd/litespm/lock_test.go`) covering the §7 scenarios: freeze round-trip from a real local index, byte-identical re-freeze, `--check` clean/hand-edited/missing, stale-manifest refusal, frozen pinning (catalog says 2.0.0, lock pins 1.0.0), not-in-lock/missing-lock refusals, SBOM carrying the lock digest, `--verify` reporting `signature=none result=unavailable`, and flag parsing. **No exporter (§5) and no identity graph (§6) exist, and the OpenAPM / Docker-profile imports are unimplemented.** See [STATUS.md](../STATUS.md) §5. Do not present the unimplemented §5/§6 parts as implemented.

---

## 1. Purpose & Invariants

A package manager is only reproducible if an install can be resolved once and then replayed byte-for-byte without re-solving. This document defines that record.

Invariants:

1. **Determinism.** `litespm.lock` is byte-for-byte reproducible from the same inputs. No timestamps, map iteration order, locale, or hostname may leak into a locked entry.
2. **Sufficiency.** The lock is sufficient to perform a **frozen** install with **no network resolution** and **no version solving**.
3. **Bindings are cryptographic.** Every entry binds the resolved bytes by artifact SHA-256 and CAS tree digest, plus the schema fingerprints of any invoked capability.
4. **Human-readable, machine-verifiable.** The manifest is authored YAML; the lock is generated YAML with a canonical JSON projection for hashing.
5. **No fabricated provenance.** A signature/provenance field is present only when a real check produced it; otherwise it is explicitly `none`/`unavailable`, never a green value.

## 2. Project Manifest — `litespm.yml`

Authored by the user, checked into the project repository. It declares intent and constraints; it never contains resolved bytes.

```yaml
# litespm.yml
schemaVersion: 1

project:
  name: acme-agent-workspace
  # scope defaults to project; user-scope installs live in the user lock
  defaultScope: project

# Direct, human-authored requirements. Transitive deps are resolved, not written here.
requires:
  - id: mcp:builtin:mcp-registry:postgres          # canonical Listing ID (ARCH/10)
    constraint: ">=1.4 <2"                          # semver / commit / digest constraint
    targets: [claude-code, codex]                   # host projections requested
  - id: skill:builtin:agent-skills:review-pr
    constraint: "1.2.0"
  - id: plugin:git:anthropic-skills:web-toolkit
    constraint: "commit:7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c"

# Policy for this project (tighten-only; see ARCH/36).
policy:
  allowSources: [builtin:mcp-registry, git:anthropic-skills]
  denyEffects: [external.delete]

# Optional cadence for `litespm lock --check` in CI.
lock:
  required: true
```

Rules:

* `id` is the canonical identifier from [10 — Domain Model](10-DOMAIN-MODEL.md). Aliases from other ecosystems are normalized through §6 before being written.
* A manifest MUST NOT encode resolved versions, digests, or artifact URLs. Those belong in the lock.
* Unknown top-level keys fail validation (forward compatibility is handled by `schemaVersion`, not by silent ignoring).

## 3. Lockfile — `litespm.lock`

Generated by `litespm lock`. Committed to the repository. One entry per resolved capability, sorted by canonical ID so output is stable.

```yaml
# litespm.lock — generated; do not edit by hand
lockVersion: 1
schemaVersion: 1
manifestDigest: "sha256:…"        # digest of the litespm.yml that produced this lock

resolved:
  - id: mcp:builtin:mcp-registry:postgres
    components:                   # component IDs materialised for this capability
      - mcp-provider:server
    source:
      identity: "builtin:mcp-registry"       # source adapter identity
      url: "https://registry.modelcontextprotocol.io/v0.1/servers/postgres"
    constraint: ">=1.4 <2"
    resolved:
      version: "1.4.2"
      commit: "7b8c9d0e1f2a3b4c5d6e7f8a9b0c1d2e3f4a5b6c"
    artifact:
      type: oci
      locator: "ghcr.io/example/postgres-mcp@sha256:…"
      sha256: "sha256:…"                    # artifact bytes
      size: 18273422
    treeDigest: "sha256:…"                  # CAS tree digest after normalization
    publisher:
      name: "Model Context Protocol"
      verified: false
    signature:
      scheme: none                          # none | minisign | cosign | sigstore-bundle
      signer: ""                            # identity, when a real check produced one
      result: unavailable                   # verified | failed | unavailable
    provenance:
      sbomDigest: "sha256:…"                # CycloneDX/SPDX document, when produced
      slsaLevel: unknown
    license: "Apache-2.0"                   # SPDX id; "NOASSERTION" when undeclared
    projections:                            # where the capability is deployed
      - host: claude-code
        scope: project
        structure: mcpServers               # host structure type (ASCII 33 §2)
    permissions:                            # declared effects with provenance (ARCH/15)
      - effect: network.outbound
        provenance: publisher_declared
    secrets:
      - name: POSTGRES_URL
        kind: env
        required: false
    schemaFingerprints:                     # SHA-256 of each tool's canonicalised inputSchema
      - capabilityId: "mcp:builtin:mcp-registry:postgres/server/query"
        fingerprint: "sha256:…"
    transport: stdio                        # stdio | streamable-http | sse
    snapshotId: "snap_2026-10-01T00:00:00Z"
    policyDigest: "sha256:…"                # digest of the effective policy decision
    planDigest: "sha256:…"                  # planHash that produced the deployment

# A stable content digest over the canonical-JSON projection of `resolved`.
lockDigest: "sha256:…"
```

Field notes:

* **`components`** are `ComponentID`s, not free text; a capability with no materialised children may have an empty list.
* **`signature`** carries `result: unavailable` until signing exists. `verified` is forbidden without a real verifier.
* **`projections`** always includes `structure` so the deployment ledger ([33](33-DEPLOYMENT-LEDGER-RECONCILIATION.md)) can reconcile by structure type, not by path alone.
* **`policyDigest`/`planDigest`** allow `audit --ci` ([36](36-ENTERPRISE-POLICY-AND-AUDIT.md)) to prove the lock corresponds to an approved plan.
* **Canonical hashing:** the lock's structural digest is RFC 8785 JCS over a JSON projection; YAML comments and ordering outside `resolved` do not affect it.

## 4. Lock Operations

| Verb | Contract |
|---|---|
| `litespm lock` | Resolve the manifest, fetch/verify artifacts, write `litespm.lock`. Idempotent and deterministic. |
| `litespm lock --check` | Recompute the lock **without writing**; exit non-zero if it would differ from the committed lock. CI gate. |
| `litespm install --frozen` | Install strictly from the lock; fail if the lock is missing, stale relative to `litespm.yml`, or an artifact hash/CAS digest mismatches. **No network resolution.** |
| `litespm lock --sbom <format>` | Emit an SBOM for the resolved graph (`cyclonedx-json`, `spdx-json`). |
| `litespm lock --verify` | Re-verify signatures/provenance/SBOM digests recorded in the lock and report per-entry results. |

`--frozen` MUST NOT silently upgrade, downgrade, add, or remove a package. Any drift is an explicit error (`LPSM-LOCK-DRIFT`), not a repair.

**Implementation note (2026-10-07).** All five verbs ship in `cmd/litespm/lock.go`. The resolver closure reads only the **local synced index** (`catalog sync` cache — zero network in `lock`/`--check`). Known, honestly-reported limits: the `--frozen` artifact-hash/CAS-digest clause awaits artifact digests in the catalog (the gate currently covers lock-side drift: missing, stale, hand-edited, not-in-lock, contradictory `--version`); `--verify` re-verifies the lock digest chain and prints the *recorded* signature/license values as `unavailable`/`NOASSERTION` — it never upgrades them to green; SBOM output carries the lock digest but is not yet validated against the CycloneDX/SPDX JSON Schemas (§4.1).

### 4.1 SBOM export

Both CycloneDX and SPDX are target formats. The export is derived from `resolved[]`, not from the live filesystem, so it can be produced and attested in CI before deployment. Each SBOM MUST carry the lock digest it was generated from so the two cannot drift.

## 5. Interoperability

Interop is bidirectional where a foreign format is lossless enough; otherwise it is **import-only with a previewable diff**. No import writes without a plan and approval ([15](15-POLICY-APPROVALS.md)).

| Foreign format | Direction | Mapping notes |
|---|---|---|
| OpenAPM `apm.yml` / `apm.lock.yaml` | import + export | Deps → `requires`; content hashes → `artifact.sha256`/`treeDigest`; deployed-file records → `projections`. Export is lossy for LiteSPM-only fields and must say so. |

**Pin against the specification, not the CLI.** OpenAPM v0.1 is published as a
normative RFC-2119 document (`microsoft.github.io/apm/specs/openapm-v01/`) with 87
`req-*` statements, inline Draft 2020-12 JSON Schemas and a `CONFORMANCE.md`
split into Producer / Consumer / Registry / Governance classes — verified
2026-10-06. The docs pages that describe these formats are explicitly *not*
normative. So the importer should validate `apm.yml` against the specification's
`manifest-v0.1.schema.json` and identify the contract by its `$id`, rather than
reverse-engineering the shapes from whatever the CLI currently emits: the
specification's own wire contract is deferred to v0.2, and a version pinned to a
working CLI draft rather than to the spec will drift the moment the CLI catches
up. The conformance classes also give the roadmap something checkable — a LiteSPM
exporter can state which classes it satisfies instead of claiming interop.
| Vercel `skills-lock.json` | import + export | Skill entries → `id` of the form `skill:…`; version/ref → `resolved`; no effect/permission data exists in that format. |
| Agent Plugins `plugin.json` | import (+ export) | `plugin.json` + `skills/` + `mcp.json` → one `plugin` capability with `skill`/`mcp` components. No trust or install semantics are imported. |
| Claude / Codex plugins (`.claude-plugin/`, `.agents/plugins/`) | import (+ export) | Marketplace manifests map to the existing `ClaudeMarketplaceAdapter` / `CodexMarketplaceAdapter` shapes. `command` sources are rejected on import. |
| Docker MCP profiles | import (+ export) | A profile's server set → `requires` + per-server `targets`; container/OCI specifics → `artifact.type: oci`. |
| MCP `server.json` | import (+ export) | `packages[]`/`remotes[]` → artifact + transport; namespace-verification assertions are preserved, not flattened. |
| `litespm.lock` | export | The native format; foreign exporters are projections of it. |

Rules:

* Import produces an **`InstallPlan` preview diff** before any write (per [31 §12](31-COMPETITIVE-LANDSCAPE-AND-ROADMAP.md) Phase 4).
* Round-trip import→export MUST NOT claim fidelity it does not have; lossy fields are reported.
* A foreign lockfile is treated as untrusted input: parsed, bounded, schema-validated, and never executed.

## 6. Canonical Identity & Alias Graph

One package is frequently published to several ecosystems. LiteSPM models **one canonical package** with **many source edges**, rather than duplicate catalog rows.

```text
                     ┌──────────────────────────┐
                     │ canonical Package         │
                     │ id: mcp:…:postgres        │
                     └────────────┬─────────────┘
        ┌─────────────┬───────────┼────────────┬──────────────┐
        ▼             ▼           ▼            ▼              ▼
   GitHub repo    npm package  MCP Registry   OCI image   Smithery
```

```go
type IdentityNode struct {
    CanonicalID string        // Listing ID grammar (ARCH/10)
    Aliases     []IdentityEdge
}

type IdentityEdge struct {
    SourceID   domain.SourceID // where the alias was found
    UpstreamID string          // source-local id (npm name, repo URL, server name)
    URL        string
    EdgeType   EdgeType
    Evidence   string          // why the edge exists (log line, API field, digest)
}

type EdgeType string

const (
    EdgeVerifiedSameProject EdgeType = "verified_same_project" // source asserts shared ownership
    EdgePublisherClaim      EdgeType = "publisher_claim"       // unverified claim
    EdgeHashMatch           EdgeType = "hash_match"            // identical artifact/tree digest
    EdgeFork                EdgeType = "fork"                  // divergent lineage
    EdgeMirror              EdgeType = "mirror"                // byte-identical mirror
    // declared / heuristic edges from the source proposal map onto the above with
    // lower confidence; they must never be rendered as verified.
)
```

Rules:

* Identity is derived from the `Listing` ID grammar plus the edge set; the edge set is the new part.
* `hash_match` requires an actual SHA-256/`treeDigest` equality — never a name or description similarity.
* `fork`/`mirror` are distinct from `verified_same_project`: a mirror is not the canonical publisher.
* Deduplication is a **presentation** concern: `search` collapses aliases to one canonical entry and lists origins. No adapter may merge two packages into one hard-coded row.
* Cross-source dedup is `DESIGNED` (`STATUS.md` §5). No resolver may depend on it until the graph exists and is tested.

## 7. Acceptance Test Sketch

A design is accepted when these can be demonstrated (each is a real workflow, not "files exist"):

1. `litespm lock` on a fixture manifest is byte-identical on two runs and on two machines.
2. `litespm lock --check` fails when an entry is edited and passes on the committed lock.
3. `litespm install --frozen` on a clean machine reproduces the exact CAS tree digests with the network disabled.
4. A tampered artifact produces `LPSM-LOCK-DRIFT` (or the artifact-hash error), never a silent pass.
5. `--sbom cyclonedx-json` and `--sbom spdx-json` validate against their schemas and carry the lock digest.
6. `litespm import apm.yml` and `litespm import skills-lock.json` each emit a previewable diff and write nothing until approved.
7. A test asserts no lock writer emits a timestamp or map-order-dependent field.
